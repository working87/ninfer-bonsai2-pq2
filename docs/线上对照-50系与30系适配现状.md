# 二、★ 决定性对比：**5090 分支到底支不支持三元**

| 仓库 | 文件数 | 含 `ternary` 的路径数 | 结论 |
|---|---|---|---|
| `headpiece747/ninfer-5090-windows`（**线上 5090 主线**） | 1,723 | **0** | **不支持三元权重**（整条线跑 NVFP4） |
| `CraneBW/ninfer-ternary-bonsai-ada`（三元 Ada 线） | 1,442 | **14** | 有，但是**另一套实现**（`ternary_rowsplit_mma.cuh`，无 `s8/small_t/wide_t` 变体） |
| **我们这棵（4090 fork 线，v1.0.6-4090）** | 1,716 | **17** | 有，**独立血统**：`_mma_s8.cuh` / `_small_t.cuh` / `_wide_t.cuh` / `_ptq1_repack.cuh` … |

> **⇒ 结论（这是我们这次工作的定位）**：
> **"三元 × 5090" 在线上是空白** —— 三元实现只存在于 **Ada（sm_89）** 与 **Ampere（sm_86）** 两条线上，
> **Blackwell（sm_120a）主线根本没有三元内核**。我们做的 120a 样品，补的正是这个空白。

# 三、逐项对比：我们 vs 线上 5090 主线

| 维度 | 线上 5090（headpiece747 / splickz） | **我们（本次 120a 样品）** |
|---|---|---|
| 源码基座 | **5090 原生 Windows 基座**（MSVC / CUDA 13.3，无 WSL2） | **4090（sm_89）fork**（`v1.0.6-4090` Windows port），我们把它扩到 120a |
| 构建标志 | `-DCMAKE_CUDA_ARCHITECTURES=120a` —— **原生命中** | 同为 `120a`，但**要我们自己补**：`NINFER_SM120` 宏 + `kTargetSmCount=170`（fork 把 120a 编死了） |
| 权重/精度 | **NVFP4**（17.36 / 18.07 GiB） | **三元 PQ2 / PTQ1**（7.74 / 7.05 GB）⇒ 显存占用只有它的一半左右 |
| KV dtype | `nvfp4` / `int8 auto`；长上下文实验用 `nvfp4` + YaRN | 120a 构建**编进了** `nvfp4`/`k8v4`/`w4a4`/`tma`（静态体检确认）✅ |
| 上下文 | 262,144（满）；实验推到 ~600K | 样品脚本给 16384 起手（**待按显存扫参**，见 `调参与扫参-速度怎么来的.md`） |
| 实测读数 | **有**：343 tok/s（DFlash2/QUASAR）、220 tok/s（MTP4）🟡 | **无**：只有编译 + 静态体检（架构 `sm_120`、宏 ×348、内核集合、依赖表、编译期断言）✅ |
| 平台 | Windows 11 原生 MSVC（主线）/ WSL2 Ubuntu（实验线） | Windows 11 + MSVC 14.51 + CUDA 13.3 |
| 分发形态 | 各自 release/源码；权重放 HF 自取 | **预编译样品 + 完整源码树 + 构建 SOP + SHA256**，并**自带权重**（Apache-2.0 已确认可分发） |
| 已知坑 | ① Prism 官方：**5090 预编译二进制解码乱跳 ⇒ 用 `120a-real` 重编**；② splickz：其 port 上 **MTP/DFlash 未验证** | ① `120a` vs `120a-real` **尚未对拍**；② MTP 接受率**未测**；③ **未上真机** |

# 四、30 系（`sm_86`）对照：两条路的取舍

| | **线上（qianchong666 / 3090）** | **我们（本次）** |
|---|---|---|
| 做法 | **重写三元内核**（v2→v10：2-bit 码字只放 smem、解码进寄存器、scale 折进片段、k-split），补丁 **71 文件 / 294 KB** | **最小接线**：白名单放行 `86` + `NINFER_SM86` 宏 + **FP8 内核排除 + stub**（共 5 个文件改动） |
| 结果 | 3090 上 prefill 1.34~1.36k、decode 74.4 🟡 | 目标先"**编过 + 起得来**"；性能优化按真机读数再决定是否值得做 |
| 优劣 | 性能有实测，但重、与本树血统不同（无法直接移植） | 轻、与本树同源；**性能未知**（可能不达 3090 的 74 t/s） |
| 共识 | **FP8 张量核墙**：两边都必须处理（他们有 `fp8_a8_stubs.cpp`，我们新写了 `ops/fp8_a8_stubs.cpp`）✅ | |

# 五、给云验证的建议（**借线上经验，别重复踩**）

1. **带对照跑**：我们的三元 5090 样品之外，**按线上口径再跑一次**（如 `--kv-dtype nvfp4|int8`、262,144 ctx、同模型不同权重），这样三元读数**有基线**，不是孤立数字。
2. **先验 Prism 那条坑**：`120a` vs **`120a-real`** 对拍（官方记的"5090 解码乱跳"处方）——若我们的 `120a` 出现抖动/退化，下一步就编 `120a-real`。
3. **验投机可用性**：MTP / DFlash2 在 5090 上是否有收益（**别人的 port 上有"未验证"记录**），按 `--spec mtp --draft-tokens 2/3/4/5 --greedy` 扫接受率。
4. **口径统一**：贪心 + 长提示 + 长输出（≥400 token）+ 丢掉首段；用 `--log-stats-interval-ms 5000` 的周期日志取数。
5. **顺手澄清一个文档债**：我们树 README 里的 `Ambolio/*` 兄弟分支链接**已 404**，向用户交付时应改注为"存档引用（见同名 fork）"，避免点空。
