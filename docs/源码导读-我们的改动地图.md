## §4 三元线逐文件（**我们的技术，可当范本**）

位置：`src/ops/linear/ternary/`（17 个文件）

| 文件 | 大小 | 职责 |
|---|---|---|
| `ternary_rowsplit_gemm.cu` | 32 KB | 主 GEMM 入口（按 T 分派到 mma/gemv） |
| `ternary_dispatch.cpp` / `.h` | 5.7 / 2.9 KB | **dispatch 层**：格式识别、形状检查、选内核 |
| `ternary_rotation.cu` / `.cpp` / `.h` | 4.8 / 3.5 / 5.7 KB | 旋转/符号变换（三元量化常用的 Hadamard 类预处理） |
| `ternary_rotation_kernels.cuh` | 7.3 KB | 旋转内核实现 |
| `ternary_rowsplit_mma_s8.cuh` | **37 KB** | **s8 MMA** 主路径（大 T） |
| `ternary_rowsplit_mma_small_t.cuh` | **56 KB** | 小 T（decode 为主）的 MMA 特化 |
| `ternary_rowsplit_mma_wide_t.cuh` | 36 KB | 宽 T（prefill/verify）的特化 |
| `ternary_rowsplit_gemv.cuh` | 18 KB | GEMV 路径 |
| `ternary_ptq1_repack.cuh` | 7.1 KB | **PTQ1 密排 repack**（把权重压成引擎要的布局） |
| `ternary_rowsplit_storage.cuh` | 4.7 KB | 存储布局 |
| `ternary_row_view.h` | 2.8 KB | 行视图（不拷贝地切行） |
| `ternary_s8_scratch.h` | 2.6 KB | scratch 预算 |
| `ternary_launch.h` | 1.6 KB | launch 配置 |

**接线**（`src/CMakeLists.txt`）：

```
346: ops/linear/ternary/ternary_rowsplit_gemm.cu
347: ops/linear/ternary/ternary_dispatch.cpp
348: ops/linear/ternary/ternary_rotation.cu
349: ops/linear/ternary/ternary_rotation.cpp
```

> **只有 4 个编译单元**；其余 13 个头文件靠 `#include` 拉取 —— **加新头文件不用改 CMake**，加新 `.cu/.cpp` 必须加一行。

⚠️ **现状**：三元内核**无 `__CUDA_ARCH__` 守卫** ⇒ sm_89 / sm_120a 都能编，但"**三元 × 120a**"**本仓库未实测**。

## §6 怎么复核我们的改动（**别只信文档**）

| 方法 | 做法 |
|---|---|
| **读移植记录** | `PORT_v1.0.5.md` / `PORT_v1.0.6.md`：逐文件决策 + 为什么这么改（含"哪些文件与上游字节相同"的声明） |
| **与上游 diff** | 本包**不含**上游基线。取上游：`https://gh-proxy.com/https://github.com/Neroued/ninfer/archive/refs/heads/master.tar.gz`（或 jsdelivr 取单文件），再与 `src/` 对比 |
| **只看我们的新增** | 目录级看：`src/ops/linear/ternary/`（全新）、三个 `*_stubs.cpp`、`PORT_*.md` |
| **看构建差异** | `src/CMakeLists.txt` 的三处 `MATCHES "^120"`（排除块）与 `CMakeLists.txt` 的架构门/宏定义 |
| **看 Windows 差异** | 搜 `_WIN32`、搜 `unsigned __int128` 的替代实现 |

> ⚠️ **一个原则**：**"能编译"不等于"能跑对"**。移植类改动（尤其涉及 MMA / shared 布局 / fp8 路径）必须**用真模型跑出可读输出**才算过 —— 这是我们在 CUDA 版本那件事上的教训（见 `复现手册-排错篇.md`）。

## ⚠️ `AGENTS.md` 是个陷阱（**把适配任务丢给 AI 时必看**）

树里带着**上游的** `AGENTS.md`，原文写着：

> *"The implementation targets `sm_120a` and is tuned on NVIDIA GeForce RTX 5090."*
> *"Additional models, **execution platforms**, large-scale/preemptive continuous batching, and priority/QoS require an **explicit product change**."*

**⇒ AI agent 读到这段极易自我设限**（判定"你这张卡不在支持面内"就停手）。
**本包手册的授权高于它**：以 `复现手册.md` 第 9 章（本索引）与 `适配案例集-把引擎搬到你的显卡.md` 为准。

## 附 · ninfer 树里的 KVMem 诊断代码

`src/ops/kvmem/`（**37 个文件**）由环境变量 **`NINFER_TERNARY_KVMEM`** 控制，**默认关闭**。
**本包的部署与性能不使用它** —— 不需要设这个变量（研究双引擎联动时可作参考）。
