# 第 0 章 · 先排除"假慢"（比调参重要）

慢有三种，**只有第二种需要调参**：

| 类型 | 症状 | 怎么排除 |
|---|---|---|
| **① 假的慢** | 你把短提示/单 token 的读数当成了真实速度 | 见 §0.1 —— **这是最常见的一种** |
| **② 真的慢** | 长提示+长输出下也慢 | 继续往下读 |
| **③ 坏环境的慢** | 只有个位数 t/s、或抖动/乱码 | 见 §5（PCIe/驱动/WDDM/回退 CPU） |

## 0.1 ★ 测量口径（**不算准就别调参**）

1. **长提示 + 长输出**：至少 400 token 输出；短提示（十几 token）测出来的都是冷启动毛刺
2. **贪心**：`--greedy`（或 `--temperature 0`）—— 采样越松，投机接受率越低，速度越假
3. **丢掉第一段**：第一个 token 含权重换入/图捕获开销
4. **让引擎自己报**：起服务时加 `--log-stats-interval-ms 5000`（默认就是 5000；**别设 0**），读周期吞吐日志
5. **同口径比较**：改一个参数 → 只比同口径的读数。**跨卡不可比**（decode 看带宽、prefill 看算力）

## 0.2 一句话公式（后面所有参数都挂在这上面）

```
decode ≈ ───────────────────────────────────
          每轮耗时（≈ 权重过一遍的时间 + KV 访问 + 调度开销）
```

- **分子** = 每轮真正吐出多少 token = `1 ＋ 投机接受链`（MTP/DFlash）
- **分母** = 每轮的成本：**权重每轮都要完整过一遍显存带宽** ⇒ **decode 天生是带宽函数**
- ⇒ **提速度只有两条路**：**要么让分子变大**（提高接受率 / 加 k），**要么让分母变小**（别让 KV 掉出显存、别关掉 CUDA Graph）

> **实测锚点（我们 4080 SUPER、贪心、ctx 16384、400 token）**：decode **226.0 t/s** ＝ **5.48 tok/round ÷ 24.2 ms/round**，接受率 **81.75%** ✅
> **反推你的读数**：如果你 ~70 t/s，那要么"每轮只拿到 1.7 个 token"（接受率低），要么"每轮 ≥35 ms"（KV 掉显存/图没开）。**先分清是哪一个，再调。**

# 第 1 章 ★ 影响速度的参数清单（按影响从大到小）

## 1.1 一级杠杆：决定"能不能待在显存里"

| 参数 | 可选值 | 影响 | 怎么选 |
|---|---|---|---|
| **`--max-context`** | 整数 token | **最大**：上下文越长，KV 越大；**KV 一旦溢出到 host，每 token 都走 PCIe，decode 直接腰斩** | **别照抄我们的 262144**（那是 16 GB 卡口径）。16 GB：≤262144；12 GB：32768~65536；8~10 GB：16384~32768 |
| **`--kv-capacity`** | `N` 或 **`auto`** | 与 `--max-context` **必须配套**（引擎硬检查：`kv_capacity` 越界⇒**启动即拒**）。`auto` = 自动留 **1024 MiB** 余量 | 不确定就写 `auto` |
| **`--kv-dtype`** | `bf16`｜`int8`｜`fp8`｜`nvfp4`｜`k8v4`｜`rk4v4`｜`rk4v4-e8` | **省显存的第二杠杆**：实测 **fp8 比 bf16 省 3,919 MiB，速度几乎不动** ✅ | **首选 `fp8`**；见 §1.2 的架构可用性表 |

**判据**：改完看日志 `capacity | KV …, runtime X GiB | free Y GiB` —— **`free` 要留 ≥1.5~2 GiB**，否则随时掉出显存。

## 1.2 ⚠️ KV 精度的**架构可用性**（选错=启动就崩）

| dtype | sm_86（30 系） | sm_89（40 系） | sm_120a（50 系） |
|---|---|---|---|
| `bf16` / `int8` | ✅ | ✅ | ✅ |
| **`fp8`** | ❌ **编不出来** | ✅ | ✅ |
| `nvfp4` / `k8v4` | ❌（stub 报错） | ❌（stub 报错） | ✅ |
| `rk4v4` / `rk4v4-e8` | ❌ | ✅（仅此构建有） | ❌ |

> **证据**：我们用 sm_86 编译时 ptxas 直接报
> `error : Feature 'mma with FP8 floating point type' requires .target sm_89 or higher` —— **FP8 张量核是 Ada(sm_89) 才有的**，所以 **30 系只能用 `bf16`/`int8` 的 KV**，别去试 `fp8`。

## 1.3 二级杠杆：让"分子"变大（投机解码）

| 参数 | 说明 | 怎么选 |
|---|---|---|
| **`--spec mtp\|dflash\|dflash2`** | 投机后端 | **MTP** 最稳（draft ≤5）；`dflash/dflash2` 支持更长草稿（K=1..15），但需要**带配套草稿头的权重**artifact，否则不可用 |
| **`--draft-tokens N`** | 每轮草稿数 | **扫 2/3/4/5**，看**接受率 × 每轮 token** 的乘积；太小赚不到，太大拒绝多反而更慢 |
| **`--lm-head-draft`** | 用 lm-head 做草稿 | 多一层验证开销；**没有实测收益就别开** |
| **采样参数** `--greedy` / `--temperature` / `--top-p` / `--top-k` / `--min-p` | **最容易被忽视**：它们**直接决定接受率** | 测速**一律 `--greedy`**；生产环境若必须采样，**把 temperature 压低**（≤0.3）再复测接受率 |

> **实测（另一档位口径）**：开投机后单流 **62.95 → 153.81 t/s** ✅ —— 但**前提是接受率高**。
> ⚠️ **反例**：小显存下投机可能是**负收益**（我们在①档量到 **41.63 → 23.69 t/s，−43%**）。
> ⇒ **投机必须实测**，不能凭"开了就该更快"。

## 1.4 三级杠杆：并发与延迟

| 参数 | 实测影响 | 怎么选 |
|---|---|---|
| `--max-concurrency N` | **每加一路，单路掉约 28%**（1→2→3 路：113.3 → 79.3 → 57.6 t/s ✅）；5 路 + 投机时**总吞吐 334.38 t/s**，但**每 lane 从 126 掉到 72（−43%）** | **单人交互就写 1**；要吞吐（多人/批处理）再加路 |
| `--prefill-chunk N` | 影响长提示的**首字时延（TTFT）**与分块节奏 | 长文档场景：先不动；TTFT 不满意再扫 |
| `--no-prefix-reuse` | **前缀缓存默认开**；关掉 ⇒ 相同前缀每轮重算 prefill | **别加这个开关** |
| `--no-cuda-graph` | 关掉 CUDA Graph ⇒ 每轮多出启动开销 | **别加**（除非排错需要） |
| `--wddm-evictable-budget` | **Windows 专属**：按总 VRAM 而不是 WDDM 进程预算来算 | Windows 上 `free` 被系统吃掉时试；**注意：GPU 不能同时在跑桌面负载** |

## 1.5 四级：真实工作量（不是"参数玄学"，是你让它干了多少活）

| 参数 | 说明 |
|---|---|
| `--no-thinking` / `--default-thinking-budget N` | **思考 token 是真实工作量**：不开思考更快，但智力掉。测速时开 `--no-thinking` |
| `--default-max-tokens N` | 默认 8192；测速时**调小**（比如 400），否则你测的是长生成的尾段 |
| `--preserve-thinking` | 保留历史思考 ⇒ 后续每轮 prompt 更长 ⇒ 更慢 |
| `--vision` / `--vision-max-tokens N` | 开视觉要加载固定的视觉 GPU 分配（默认 scratchpad 8192）；**纯文本场景别开** |
| `--host-kv-mib`（默认 8192） / `--host-state-slots`（默认 8） / `--device-state-slots` | KV/状态的 host 侧与检查点容量；**host 侧越大，能容纳越多但搬运越多** |
| `--device N` | 多卡选卡；**选错卡（或选到被占用的卡）会慢得莫名其妙** |

# 第 2 章 ★ 扫参流程（照这个顺序做，别乱试）

> 原则抄我们自己的手册：**从"最影响能不能跑起来"的开始；一次只改一个；每步都记录。**

| 步 | 扫什么 | 怎么做 | 判据 |
|---|---|---|---|
| **1** | **能不能跑起来** | 先只给 `--max-context 16384 --kv-capacity auto --kv-dtype fp8` | 日志 `listening` + `curl /v1/models` = 200 |
| **2** | **步长：上下文** | 16384 → 32768 → 65536 → 131072 → 262144，逐档加 | 每档看 `runtime` / `free`；**`free ≥1.5 GiB` 才继续加** |
| **3** | **KV 精度** | 在你不爆的最高上下文上，`fp8` ↔ `int8` ↔ `bf16` 各测一遍 | 取"能跑且最快"；**fp8 通常白赚** |
| **4** | **投机** | `--spec mtp --draft-tokens 2/3/4/5`（配 `--greedy`） | 记录 **接受率** 与 **tok/round**，取乘积最大 |
| **5** | **并发** | `--max-concurrency 1/2/3` | 单人取 1；要吞吐再往上，并接受单路下降 |
| **6** | **分档阈值** | `kTernaryWideMinTokens`、**`kTernaryS8MinTokens`（int8 档起点，默认 33）**（编译期常量，见源码导读 §9） | 只有你自己重编时才动；改完**必须重测**。★ **老卡 / 中低端卡（原生 int8 张量核但 SM 少）请看 `调参-按卡重拟合int8档起点-自改配方.md`** —— 那个阈值的交叉点**是卡的属性**（我们卡上 T≈32~40、一张 66 SM 的 Ada 卡上 T≈17），配方含精确 diff、探针验法、三层判据与回退 |
| **7** | **采样** | `--greedy` vs 你的生产采样参数 | 生产参数一旦定下，接受率要重测 |

## 2.1 记录表模板（**复制过去填**）

| 配置 | max-context | kv-dtype | spec/draft | concurrency | runtime(GiB) | free(GiB) | decode t/s | prefill t/s | 接受率 / tok·round⁻¹ |
|---|---|---|---|---|---|---|---|---|---|
| A | 16384 | fp8 | 无 | 1 | | | | | |
| B | 65536 | fp8 | 无 | 1 | | | | | |
| C | 65536 | fp8 | mtp/3 | 1 | | | | | |
| D | 65536 | fp8 | mtp/5 | 1 | | | | | |

> **择优标准**：**能稳定跑起来的前提下最快**，不是"参数最大"。参数拉满导致溢出 = 反而最慢。

# 第 3 章 按显存的推荐起点（**从这些开始扫，别从 262144 开始**）

| 你的显存 | 起手配置 | 说明 |
|---|---|---|
| **24 GB+** | `--max-context 262144 --kv-capacity auto --kv-dtype fp8 --max-concurrency 1` | 我们的基准档位 |

> ★ **档位更正（2026-09-27）**：这一行是**上下文 262144 的显存口径**，与 DFlash2 无关。**DFlash2 K=7 本身归 16 GB 档**（启动件 `start-8085-dflash2.bat`，32768 / fp8，额定 ≥16 GB，权重 9.10 GiB）⇒ **16 GB 卡就该用 DFlash2 K=7**，不必等到 24 GB。
| **16 GB** | `--max-context 65536~131072 --kv-dtype fp8` | 权重 7.74 GB，KV 要留位置 |
| **12 GB** | `--max-context 32768~65536 --kv-dtype fp8` | ⚠️ **别抄 262144**（8.54 GiB 运行时口径是 16 GB 卡） |
| **10 GB** | 换 ③均衡档（`bonsai2_27b_ptq1.ninfer`，权重显存 5.52 GiB）或 `--max-context 16384` | ③档就是 8~10G 这个位置的 |
| **8 GB** | 走 ①档（llama-KVMem）或 ③档 + 短上下文 | ②档权重本身就 6.70 GiB |

# 第 4 章 "我这很慢"的六个真因（对号入座）

| # | 真因 | 症状 | 处方 |
|---|---|---|---|
| **1** | **照抄了 262144** | 能起但慢、日志 `free` 很小 | 砍上下文到能留出 1.5~2 GiB；见 §3 |
| **2** | **短提示/单 token 口径** | "只有 47 t/s"这种怪值 | 换长提示+长输出重测（§0.1） |
| **3** | **采样太松 ⇒ 接受率跌** | tok/round 接近 1（投机白开） | `--greedy` 或降 temperature 后复测 |
| **4** | **关了 CUDA Graph / 前缀缓存** | 每轮固定开销大、重复前缀反复 prefill | 去掉 `--no-cuda-graph` / `--no-prefix-reuse` |
| **5** | **小显存上硬开投机** | 开了投机反而更慢 | 关掉投机，或先降上下文再试（①档实测 −43%） |
| **6** | **多路抢占** | 单路 113 → 3 路只剩 57 | 单人 `--max-concurrency 1`；要吞吐就接受单路下降 |

# 第 5 章 机器侧（不是参数，但更常见）

| 项 | 判据 | 处方 |
|---|---|---|
| **PCIe 链路** | `nvidia-smi --query-gpu=pcie.link.gen.current,pcie.link.width.current --format=csv` | x16 Gen4 为正常；**掉到 x8/Gen3 会砍 host-KV 路线的速度** |
| **降频/功耗墙** | `nvidia-smi --query-gpu=clocks.sm,clocks.mem,power.draw,utilization.gpu --format=csv -l 1` | 采样期间看是否撞功耗墙；Windows 电源计划设"高性能"、NVIDIA 面板设"最高性能优先" |
| **显存被占** | 日志 `free` 行 | 关浏览器/ComfyUI/其他推理进程 |
| **驱动** | 需要支持 CUDA 13.x 的驱动 | 引擎用**驱动侧** CUDA 运行库（**不必装 CUDA Toolkit**），但驱动太老会 `0xC0000135` 或行为异常 |
| **Windows vs Linux** | WDDM 有内存预算与驱逐 | 可试 `--wddm-evictable-budget`；Linux/WSL 通常更稳 |
| **回退 CPU（最贵的坑）** | decode 只有 **1~2 t/s** 且不报错 | 查日志 `CPU model buffer size`；这类"静默回退"不是性能问题，是**没走 GPU** |

# 第 6 章 判定"算不算正常"（别拿 226 当靶子）

**decode 看带宽，prefill 看算力** ⇒ 不同卡天生不同：

| 卡 | 显存带宽 | decode 预期 | 说明 |
|---|---|---|---|
| **4080 SUPER** | 736 GB/s | **226.0** ✅ | 我们的基准 |
| 4090 / 4090D | 1,008 GB/s | ~280~310 | 🟡 |
| 5090 | ~1,792 GB/s | ~450~550 | 🟡 |
| 4070 Ti SUPER 16G | 672 GB/s | ~100.8 | 🟡 社区实测 |
| 3090 | 936 GB/s | ~250~280 | 🟡（但张量核少 ⇒ prefill 掉） |
| 3060 12G | 360 GB/s | ~110~130 | 🟡 |

> **按带宽折算**：4070 SUPER（504 GB/s）≈ **75 t/s** 上下 —— **跑到 70 不是"坏了"，是这张卡的正常水位**。
> 想越过水位，只能从 **§1.3 接受率** 和 **§1.4 每轮开销** 里抠，别指望线性外推。

> ★ **prefill 偏慢的老卡（30 系 / SM 少的 Ada）还有一条专门的路**：三元线性层的 **int8 档起点阈值**
> （`kTernaryS8MinTokens`，默认 33）是**卡的属性**，不是普适最优 —— 我们卡上交叉点在 T≈32~40，
> 而一张 66 SM 的 Ada 卡上是 **T≈17**。要动它得自己重编一次，**配方、精确 diff、探针验法、三层判据、
> 回退开关全在 `调参-按卡重拟合int8档起点-自改配方.md`** 里。

**四条验收判据**：① `listening` + HTTP 200 ② 贪心输出通顺（金标准 `The capital of France is` ⇒ `Paris`）③ 长输出 400 token 不抖动/不退化 ④ 长提示+长输出读数落在上表量级内。

# 第 7 章 ★ KVMem（长上下文）技术在引擎里，但**默认关闭 —— 别开**

> **这一章只为一件事**：告知接手的 agent —— **这个引擎带 KVMem 技术，但默认是关的**。你**什么都不用做**。

| 开关（默认全关，只认 `=1`） | 作用 |
|---|---|
| `NINFER_TERNARY_KVMEM` | KVMem 总开关 |
| `NINFER_TERNARY_KVMEM_WINDOW_ASSEMBLY` | 按选择装配窗口并 arm 载体 |
| `NINFER_TERNARY_KVMEM_SEMANTIC` | 语义档（按分数装窗）；不设＝压力档，**逐位不变** |

**为什么别开**：① 默认档与出厂**逐位一致**，开了才动数值；② 它要**配套的池/上下文配置**（"池 ≠ 上下文"那一套），不是"设个 env 就变快"；
③ 开错是**静默的**（只在日志里多出窗口装配那类行、读数悄悄变）⇒ 拿它当性能结论会得到**假绿**。
**要研究它**：自己编一支 + 先过质量关（可核对答案 + 负控变红）再谈性能。详细口径、源码行号与我们的两棒实测见 `引擎-模型-参数对照表.md` **§6.5**。
