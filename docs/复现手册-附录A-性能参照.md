# A.0 先记住这一条

> **decode 看带宽，prefill 看算力。**

| 阶段 | 瓶颈 | 受什么支配 |
|---|---|---|
| **decode**（逐字生成） | **显存带宽** | 带宽越高越快 |
| **prefill**（读提示） | **算力** | 张量核越多越快 |
| 两者**都**吃 | 显存容量 | 决定**上下文能开多大** |

**⇒ 所以下面这些组合都是正常的：**
- **老卡 decode 不差、prefill 很差**（如 V100：HBM2 带宽高，但张量核老）
- **新卡两项都强**（如 5090）
- **decode 比我们高、prefill 比我们低**（算力/带宽配比不同）

**⇒ 别用单一数字判断复现成功与否。** 判定规则见 §A.3。

## A.1b ★ 两档对照（**同一份引擎、同口径实测**）

我们交付两个档，**用同一个引擎二进制**（SHA256 一致），只换权重：

| 指标 | **极速档 PQ2** | **均衡档 PTQ1** | 差距 |
|---|---|---|---|
| 量化 | `PQ2_0_G128`（2.125 bpw） | `PTQ1_0`（1.75 bpw，密排） | — |
| 模型文件 | 7.74 GB | **7.05 GB** | 小 0.69 GB |
| **权重显存** | 6.70 GiB | **5.52 GiB** | **省 1.18 GiB** |
| **运行时显存** | 8.54 GiB | 8.54 GiB | **一样**（KV 池相同） |
| **prefill**（4,044-token） | **2,230 t/s** | **2,010 t/s** | PTQ1 慢 **10%** |
| 冷缓存确认 | `cache 0 (0.0%)` ✅ | ✅ | — |
| 两档答案 | — | **逐字相同** ✅ | 数值路径一致 |
| decode | ≈210 t/s（**旧二进制读数**） | ≈166 t/s（**旧二进制读数**） | ⚠️ **本轮未重测** |

> **★ 一句话选档**：**显存紧 ⇒ PTQ1；要最快 ⇒ PQ2。**
> ⚠️ **"省"的是权重，不是峰值** —— 运行时两档相同。所以：
> · 瓶颈是"**权重装不下**" ⇒ PTQ1 的 1.18 GiB 是关键
> · 瓶颈是"**总显存**" ⇒ 两档差别不大
>
> ⚠️ **decode 那两格是更早二进制的读数，本轮没重测**。要引用 decode，请自己在同口径下扫一遍（主文档第 7 章）。
> ⚠️ **prefill 的旧读数是 1,980 / 1,770** —— 已被上表 **2,230 / 2,010** 取代（同一份引擎重测）。

# A.3 ★ 判定规则（**怎么算复现成功**）

| 现象 | 判定 | 下一步 |
|---|---|---|
| decode / prefill 都在预期 **±30%** 内 | ✅ **复现成功** | 收工 |
| **decode 高、prefill 低**（或反之） | ✅ **正常** | 收工（配比不同而已） |
| 落在预期但**明显偏慢**（±30%~±50%） | 🟡 **可用，但没调优** | 做参数扫描（主文档第 7 章） |
| **decode 只有个位数 / 1~2 t/s** | ❌ **不是性能问题** | **静默回退 CPU** ⇒ 排错篇 §4.1 |
| **PPL 是几百** | ❌ **不是性能问题** | **数值错了** ⇒ 排错篇 §3.1 |
| **prefill 与提示长度无关（平的）** | ❌ **适配未完成** | 在慢内核上 ⇒ 主文档 4.3 |
| **起服就退出** | ❌ | 排错篇 §1 |

# A.4 参数对性能的影响（**实测过的取舍**）

| 参数 | 影响 | 实测数据 |
|---|---|---|
| **并发路数** | 每加一路，**单路掉约 28%** | 1路 113.3 → 2路 79.3 → 3路 57.6 t/s ✅ |
| **5 路 + 投机** | 总吞吐 **334.38 t/s**、`batch 4.04`（真批处理）；**但每 lane 从 126 掉到 72 t/s（−43%）** | ✅ |
| **KV 精度 → fp8** | 省 **3,919 MiB**，速度**几乎不动** | ✅ |
| **上下文长度** | 越长越慢（瓶颈从权重转到 KV） | 🟡 参照：86.9 @8k → 35.0 @191k |
| **投机（MTP）** | decode 明显受益 | ✅ 单流 62.95 → 153.81 t/s（另一档位口径） |
| **分档阈值** | 配错会让多路踩慢内核 | ✅ 9 → 41 使多路 **+51%** |
