> **单位说明**：模型文件为**十进制 GB**（1 GB = 1000³ B）；显存/权重行为 **GiB**（1 GiB = 1024³ B）。
> 换算：① PQ2 8.31 GB = 7.74 GiB ｜ ② KVMem 5.95 GB = 5.54 GiB ｜ ③ PTQ1 7.05 GB = 6.56 GiB。

**怎么选**：显存小/机器弱/不想编 ⇒ **①**；要读超长材料 ⇒ **只能 ①**；显存紧要 ninfer 速度 ⇒ **③**；要最快 ⇒ **②**。

> ⚠️ **①档默认是"保命参数"**（故意压到最保守，防对方刚跑就爆显存/爆内存）—— **不是推荐性能配置**，机器够好就该调大（见该档 `README.md` §4）。
> ⚠️ **③档省的是权重、不是峰值**（KV 池两档相同）⇒ 若瓶颈是"总显存"，③②差别不大。
> ⚠️ **别在同一张卡上同时常驻两个 ninfer 档**（每个约 8.5 GiB）；换档前**必须确认显存落回基线**。

### 包的整体结构（**三档各自独立、结构一致**）

> ## ★ 重要：三档是**分别分发**的
> **每个包都必须自带全套**（手册 / 许可 / 判据 / 校验），**不能依赖别的包**。
> 所以 `docs\` 与 `licenses\` 在**三档里各有一份**，内容按档定制。

```
<单独发出去的包>\
├─ engine\        引擎 + 依赖 dll（必须与 exe 同目录）
├─ model\         权重
├─ licenses\      ★ 许可与署名（分发必须整目录随附）
├─ docs\          ★ 手册全套（复现手册 / 排错篇 / 性能附录 / 交付件清单 / 兜底方案 / **适配案例集** / **构建与ABI校验-SOP** / **源码导读**）
├─ start-*.bat    启动件（纯 ASCII）
├─ 判据.txt       就绪判据 / 期望读数 / 常见故障
├─ README.md      本档说明
├─ SHA256SUMS.txt 本档校验
└─ src-tree\      （**仅 ninfer 两档**：完整可编译源码树）
```

**三档结构相同**；差异只有：**引擎线**（llama / ninfer）、**权重文件**、**启动件端口**、**许可的具体内容**。

## 二、对方拿到后的最短路径

### ①档（llama-KVMem）——**拿来即用，不看显卡**

| 步 | 做什么 |
|---|---|
| 1 | 校验 SHA256 |
| 2 | **把包挪到纯 ASCII 路径** |
| 3 | 双击 `start-lowvram.bat` |
| 4 | `GET /v1/models` ⇒ 200（约 17 s） |

**⇒ 没有"按显卡适配"这一步。** 机器够好想跑快，再按该档 `README.md` §4 调参。

### ninfer 两档（PQ2 / PTQ1）——**按算力分路**

| 他的卡 | 走哪条 | 做几件事 |
|---|---|---|
| **40 系**（`8.9`） | **开箱即用** | ① 校验 SHA256 ② 双击 `start-8084.bat`（或 `start-8085.bat`） ③ 做参数扫描 ④ 对性能 |
| **50 系**（`12.0`） | **改一行重编** | ① 树复制到 **纯 ASCII 路径** ② 改 `build_v1.0.8.bat` 的 `=89` → `=120a` ③ 编 ④ 扫参数 |
| **30 系**（`8.6`） | **接线 + 过编译门** | ① 放行 `86` ② 补 `NINFER_SM86` 宏 ③ 按 shared 预算重调内核 ④ **重测分档阈值** ⑤ 四条验收 |
| **20 系 / V100 / A100** | **我们没做过** | 手册第 5 章给**社区已验证方案**（注意：他们走的是 W8/NVFP4，**不是三元**） |
| **H100** | 🔴 **ninfer 全生态空白** | 走 Prism fork |
| **非 N 卡**（A/I/Apple/CPU） | **换成 Prism fork** | 手册第 6 章；⚠️ **选错后端会静默回退 CPU** |

> 💡 **显存小 / 机器弱的机器，优先试 ①档** —— 它不吃特定显卡，也不用编译。

## 三、三条必须在交付时一起说的话

1. **模型权重是"转换后的衍生品"，不是官方原件**
   → SHA256 与官方 `.gguf` **必然不同**，别互相核对
   → ninfer 两档的改动逐条声明（含**借用的 MTP 头**与**视觉塔载荷**）见各档 `licenses\THIRD_PARTY_NOTICES.md`

2. **署名（Apache-2.0，官方请求原句）**
   → **"Created using Bonsai by Prism ML."**
   → 上游两层：Bonsai 2 27B © Prism ML, Inc. ｜ Qwen3.8-27B © Alibaba Cloud（**MTP 头也来自这里**）

3. **ninfer 两档的引擎来源是 dev fork，不是生产引擎**
   → 生产引擎**不支持三元**（它只认 9 种格式，没有 `PQ2_0`）
   → 这是**有意为之**，如实标注
   → （①档走的是 llama.cpp 的 KVMem fork，**Apache-2.0 可再分发，已向作者确认**）

## 四、边界（**先说清楚做不到什么**）

### ninfer 两档（PQ2 / PTQ1）

| 项 | 状态 |
|---|---|
| `--disk-cache` | **不支持**（这条线没这个参数，加了起不来） |
| `--kv-capacity` | **必须 ≥ `--max-context`**（引擎硬检查） |
| `--spec dflash` + `--vision` | **不能同开** |
| 序列硬顶 | **262144**（模型原生属性）⇒ **要读 1M 级语料必须走 ①档** |
| 多卡 / 非 40 系 / Linux | **未验** |
| 并发 | **固定单路最稳**；每加一路单路掉约 28% |
| 树里的 KVMem 代码 | **默认关闭**（`NINFER_TERNARY_KVMEM`），**本手册不使用** |

### ①档（llama-KVMem）

| 项 | 状态 |
|---|---|
| **`--kvmem-sink-tokens`** | **必须 ≥ 4096 且必须显著小于 `--kvmem-budget`** —— **sink = budget ⇒ 每个请求 HTTP 500** |
| **`--kvmem-gen-reserve`** | **单次生成上限**（含思考）；超了会被截断 |
| **MTP** | 默认**关**；小显存下 MTP 是**负收益**（decode **41.63 → 23.69 t/s，−43%**）⇒ **别为"看着高级"去开** |
| **视觉** | 带 `mmproj` 但未在本档实测；视觉编码器默认放 GPU ⇒ 8 GB 卡上**别开**（要开先加 `--no-mmproj-offload`） |
| 它**不是**"记忆仓库" | 只装**注意力 KV（16 层）**，**装不了 ninfer 侧的 48 层 GDN 递归态** |
| 1M 上下文 | 🟡 需 **≈40 GB 内存**（文档记载 988K 实测）⇒ 弱机别想 |
| 路径 | **必须纯 ASCII** |
| 通用 | **路径必须纯 ASCII**（中文会让引擎报错，**也会让 CMake 构建失败**） |
